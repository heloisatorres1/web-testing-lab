# BUG-010: Petstore stores pets that break its own contract

| | |
| --- | --- |
| **System** | Swagger Petstore |
| **Environment** | https://petstore.swagger.io/v2, contract `/swagger.json` (Swagger 2.0) |
| **Test user / data** | None (public API) |
| **Severity** | Major (clients that trust the contract can crash on `findByStatus` results) |
| **Priority** | P2 |
| **Found by** | TC-PS-005 (contract check on listed pets), isolated as TC-PS-010 |
| **Reproducibility** | Always |
| **Status** | Open |

## Steps to reproduce

1. `POST /pet` with body `{ "id": 900123456789, "photoUrls": [] }` (no `name`, which the `Pet` definition lists under `required`).
2. `GET /pet/findByStatus?status=available`.

## Expected result

Step 1 is refused (400 or 405 "Invalid input", as documented for the operation). Every pet returned by step 2 has a `name`.

## Actual result

Step 1 answers **200** and stores the pet. Step 2 returns pets without `name` (first seen with id `9223372036854776000`).

## Evidence

`tests/api/petstore.spec.ts` → TC-PS-010, marked as an expected failure with the exact request. The Ajv validation error from the first run:

```
pet 9223372036854776000 matches the contract:
[{"instancePath":"","schemaPath":"#/required","keyword":"required",
  "params":{"missingProperty":"name"},"message":"must have required property 'name'"}]
```

## Notes

Because the API is shared, TC-PS-005 now validates only the pet created by the test, so other people's malformed data does not fail the run. The contract violation lives in TC-PS-010 alone.
