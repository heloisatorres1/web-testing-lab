# BUG-011: Secondary text falls below the WCAG AA contrast ratio on every page

| | |
| --- | --- |
| **System** | QA Workspace (my own app, tested black-box) |
| **Environment** | https://heloisatorres1.github.io/qa-workspace/, light theme, Chromium; axe-core 4.x with the `wcag2a` + `wcag2aa` rule set |
| **Test user / data** | Built-in fixture data |
| **Severity** | Major (serious impact in axe terms: hints, legends and keyboard shortcuts are hard to read for users with low vision) |
| **Priority** | P2 |
| **Found by** | TC-QW-020 (automated axe scan) on Overview, Capture, Triage and Releases |
| **Reproducibility** | Always |
| **Status** | Open |

## Steps to reproduce

1. Open the Overview page in the light theme.
2. Run an axe scan with the WCAG 2 A/AA rules (`npm run axe -- "https://heloisatorres1.github.io/qa-workspace/#/"`).

## Expected result

No `color-contrast` violations: body text needs a contrast ratio of at least 4.5:1.

## Actual result

Rule `color-contrast` (serious) on **23 elements** on Overview and **10** on Capture, all with the same cause: the muted text colour `#6b7a86` on white (`#ffffff`) gives **4.41:1**, and on the key-cap background (`#fafbfa`) **4.25:1**. Affected: field hints (`#…-hint`), legend labels, `.subtle` text, and the `.kbd` shortcut badges.

```
.kbd: insufficient color contrast of 4.25 (foreground #6b7a86, background #fafbfa, 11px)
#_r_2_-hint: insufficient color contrast of 4.41 (foreground #6b7a86, background #ffffff, 13px)
```

## Evidence

Full violation JSON is attached to each TC-QW-020 run in the Playwright report (`axe.json`). The four scans are marked as expected failures in `tests/qa-workspace/smoke.spec.ts` until the fix ships.

## Notes

- One colour token causes every instance, so the fix is a single change: darken the muted text to about `#5f6e7a` (≈ 5.1:1 on white) and re-check the dark theme.
- Found by testing my own app from the outside with a tool its own test suite does not run. That is the point of this repo's QA Workspace suite.
